# Импорт выгрузки КАБИС

## Результаты проверки переданной выгрузки

Архив содержит один файл с 37 836 записями в формате с лидером, каталогом полей и разделителями, похожем на ISO 2709 / UNIMARC. Это **не CSV и не DBF**; для подполей в данной выгрузке используются текстовые маркеры вида `^A`. Импортёр рассчитан на этот наблюдаемый вариант, а не на любые файлы MARC/КАБИС.

Кодировка **PTCP154 (Python `ptcp154`) — наиболее обоснованный вариант**: все поля выгрузки декодированы без ошибок, а в проверенных названиях корректно отображаются ә, ғ, қ, ң, ө, ұ, ү, һ, і. Например, `1-класта математиканы оқыту`. Для окончательного подтверждения необходимо сверить выборку названий с оригинальной системой КАБИС: успешное декодирование само по себе не доказывает правильность каждого символа и каждого поля.

- 37 703 записей имеют GUID и непустое поле `200^A` и допускаются к пробному импорту.
- 133 записи отклонены: нет непустого `200^A`. Во всех обнаружено поле `461`, которое может описывать связанную запись; автоматически подменять им заглавие нельзя. В JSON-отчёте сохранены GUID, смещение и некоторые поля для ручной проверки.
- 37 836 исходных GUID уникальны в выгрузке. Другие дубликаты по содержанию не проверялись.
- В пробном импорте в отдельную пустую тестовую базу добавлены 37 703 записи. При повторном импорте все 37 703 уже существовали, новых не добавилось. Все сохранённые исходные байты проверены по SHA-256; SQLite `integrity_check` вернул `ok`, нарушений внешних ключей не найдено. Реальная рабочая база не изменялась.

Исходная выгрузка и тестовая база не входят в архив проекта. JSON-отчёт может содержать библиотечные метаданные и исходные GUID; храните его в соответствии с правилами университета.

## Сопоставление полей

| Исходное поле | Поле QOR | Правило |
| --- | --- | --- |
| `001` | `kabis_sources.source_id`, `source_id_raw` | GUID нормализован; исходная строка сохранена отдельно |
| Вся запись | `kabis_sources.raw_record`, `raw_sha256` | Исходные байты без преобразования и SHA-256 |
| `200^A` | `title` | Обязательно; остальные подзаголовки пока не переносятся |
| `700^A`, `710^A` | `authors` | Список как в выгрузке |
| `210^C`, `210^D` | `publisher`, `year` | Год переносится только если ровно 4 цифры |
| `101^A` | `language` | Только однозначные `каз`, `рус`, `eng`; остальные оставлены пустыми |
| `900^C` | `kind` | Явные учебник и учебные пособия → `textbook`, остальные → `material` |
| `606^A`, `610^A` | `keywords` | Объединение без повторов |
| `856^U` | `url` | Первая http/https ссылка, без проверки доступности или прав |
| `010^A` | `isbn` | Как указано в источнике, без проверки контрольной суммы |
| `675^A` | `udc` | Как указано в источнике, без проверки корректности |
| `621^A` | `bbk_candidate` | Предполагаемый ББК; требуется подтверждение |

ISBN из `010^A`, УДК из `675^A` и предполагаемый ББК из `621^A` переносятся в отдельные поля; значение 621 требует сверки с документацией и библиотекарем. Остальные поля, включая экземпляры, сведения о доступности и дополнительные части названия, **ещё не перенесены в отдельные поля QOR**. Они остаются в исходных байтах записи, но в интерфейсе сейчас не отображаются. В частности, `461` нельзя автоматически считать названием без проверки библиографом. Факт наличия URL не означает, что доступ к материалу законен или возможен.

`GET /api/items/{id}/source` возвращает GUID, исходную строку идентификатора и хеш записи, если карточка импортирована из КАБИС. Исходные байты хранятся в SQLite, но по API не выдаются. CSV-экспорт не включает эти данные; он **не является полной резервной копией**. Для полного сохранения используйте SQLite backup.

## Подготовка

1. Сделайте независимую резервную копию базы и проверьте её восстановление. Используйте тестовую копию проекта и базы, не production.
2. Сверьте кодировку и сопоставление полей с библиотекарем. Проверьте данные об авторах, языках и типах, а также `rejected_records` в отчёте.
3. Распакуйте из архивa КАБИС единственный файл в `kabis.bin`. Имя исходного файла в ZIP может отображаться неверно из-за кодировки имени. Не изменяйте байты файла. Например, положив архив под именем `kabis.zip` в папку проекта:

```bash
python -c "import zipfile,shutil; z=zipfile.ZipFile('kabis.zip'); f=[x for x in z.infolist() if not x.is_dir()]; assert len(f)==1, 'Ожидался один файл'; src=z.open(f[0]); out=open('kabis.bin','xb'); shutil.copyfileobj(src,out); out.close(); src.close(); z.close()"
```

Если `kabis.bin` уже существует, команда остановится, не перезаписывая его.

## Предварительная проверка без записи

Из корня проекта с активированным Python-окружением:

```bash
python -m app.kabis_import kabis.bin --db data/qor.db --report dry-run.json
```

Отчёт покажет количество записей, отклонённые записи, хеш исходной выгрузки, приблизительное сопоставление языков/типов и, если указана существующая база, число новых, неизменившихся и изменённых источников. В dry-run базу можно не указывать. Каждому запуску нужно новое имя отчёта — существующие файлы не перезаписываются.

## Импорт после проверки

**Остановите QOR и другие процессы, которые могут писать в базу, на всё время резервирования и импорта.** SQLite backup выполняется до начала транзакции; остановка других писателей необходима, чтобы резервная копия соответствовала состоянию перед импортом. `data/qor.db` должен уже существовать и иметь совместимую таблицу `items`.

По умолчанию при любой отклонённой записи импорт блокируется. Только после проверки отчёта библиотекарем можно явно разрешить пропуск отклонённых записей:

```bash
python -m app.kabis_import kabis.bin --db data/qor.db --report import-result.json --apply --allow-rejects --backup backup-before-import.db
```

Команда создаёт отдельную резервную копию и выполняет запись всех допустимых новых записей в одной транзакции. Любая ошибка записи откатывает транзакцию. Существующая база, отчёт и резервная копия не перезаписываются. Чтобы восстановить базу из резервной копии, остановите QOR, сохраните копию текущей базы, затем замените файл базы его резервной копией; отдельно учитывайте WAL-файлы и проверяйте восстановление до эксплуатации.

При повторном запуске GUID не создаются повторно. Если данные той же записи в новой выгрузке изменились, импортёр **пропустит** их и отметит `changed_skipped`; автоматического обновления пока нет. Совпадения по названию и ранее внесённые вручную записи не объединяются. Автоматического импорта 133 отклонённых записей тоже нет.

Отчёт сначала создаётся со статусом `prepared_not_committed`. После успешного сохранения транзакции он обновляется до `committed`. Если обновление отчёта не удалось, команда отдельно предупредит об этом: проверьте состояние базы и результат сравнения перед повторным запуском.

## Текущие ограничения

Нет веб-интерфейса импорта КАБИС, автоматического обновления исходных записей, решения спорных полей или библиографической дедупликации. Локальные роли сотрудников добавлены, но их безопасность ещё не прошла независимый аудит. Импорт выполняется из командной строки. Поиск QOR остаётся лексическим/fuzzy, а не семантическим, и не прошёл нагрузочные испытания на полном каталоге. Прототип нельзя публиковать в открытом доступе без авторизации и защиты административных функций.

Для записей, ранее импортированных старой версией, заполнение пустых ISBN/УДК/621 производится отдельной командой `app.kabis_backfill` после резервирования и миграции схемы; см. README. Непустые значения не перезаписываются.
